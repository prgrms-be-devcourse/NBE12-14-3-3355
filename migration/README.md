# Kotlin 마이그레이션 협의

팀원이 전환 범위와 합의 내용을 확인할 수 있도록 이 폴더에 기록한다. 확정 내용과 제안은 구분하며, 아직 소스 전환은 시작하지 않았다.

3차 과제 요구사항에 맞춘 기획서 초안은 [PROJECT_PLAN.md](PROJECT_PLAN.md)에서 관리한다.

## 확정된 방향

- 일부 파일만 전환한 상태로 나누어 반영하지 않고, 전환 대상 전체를 Kotlin으로 바꾼 결과를 한 번에 반영한다.
- 합의 문서는 Git으로 공유할 수 있는 `migration/`에 작성한다.
- 운영 Java 코드 전체를 전환하고 테스트 코드는 Java로 유지한다.
- `/api/v1`, 요청·응답·인증·오류·추천 정책과 DB 구조·데이터를 유지한다.
- 비즈니스 로직은 유지한다. 이번에는 마이그레이션만 진행하고 관리자 추천 갱신 기능은 추후 다시 검토한다.
- Java 테스트는 호출 호환성을 위한 최소 수정만 허용한다. 검증 내용·기대값은 유지하며 수정 파일·이유·전후 호출을 문서에 기록한다.
- Java 25·Spring Boot·DB·주요 라이브러리 버전을 유지하고 Kotlin 지원 설정만 추가한다. 호환성 때문에 기존 버전 변경이 필요하면 근거를 제시하고 재협의한다.
- 완료 전 clean build, 기존 Java 테스트, 서버 기동, 주요 API·추천 CLI를 검증한다. 성능 수치는 참고 자료로 기록하며 전환 완료의 통과·실패 기준으로 삼지 않는다. (Q7, Q14)
- null 허용 범위는 기존 DB·요청·외부 API 계약을 기준으로 보존한다. 필수값만 non-null로 표현하고, 컴파일을 맞추기 위한 무분별한 `!!`나 임의 기본값은 사용하지 않는다. (Q8)
- DTO는 기존 Java 호출·JSON·동등성 동작과 호환되는 경우 `data class`를 활용한다. JPA 엔티티는 일반 `class`로 전환하여 기존 동등성·지연 로딩 동작을 보존한다. 복합키처럼 기존에 값 비교를 정의한 타입은 해당 계약을 유지한다. (Q9)
- 서버 실행 방법·환경변수·추천 사전 계산 Gradle 명령을 유지한다. Kotlin 전환으로 내부 진입점이 달라지면 빌드 설정을 맞추고, 불가피한 외부 명령 변경은 별도 협의·문서화한다. (Q10)
- 전환 대상 파일의 기능 수정은 마이그레이션 완료 후 진행한다. 전환 기간에는 병행 기능 변경을 넣지 않는다. (Q11)
- 에이전트가 커밋 분리와 실행까지 진행한다. 커밋 전 사용자 검토는 요청하지 않고, 각 커밋의 변경·검증 결과를 문서에 기록한다. 원격 push·PR 병합은 이 합의에 포함하지 않는다. (Q12)
- 현재 Java 기준 빌드·테스트·API·추천 성능 결과는 별도 [BASELINE.md](BASELINE.md)에 기록한다. 미측정 항목은 완료로 표시하지 않는다. (Q13)
- 성능 개선·회귀 판단과 반복 측정은 추후 검토한다. 현재 확보한 결과는 보존하며, 성능 목표 달성 여부로 마이그레이션 완료를 보류하지 않는다. (Q14)
- 기존 Java 테스트 실패 시 Kotlin 구현의 호환성 문제를 우선 확인한다. 테스트 삭제·비활성화·기대값 변경으로 통과시키지 않으며, 최소 호출 수정은 이유와 함께 기록한다. (Q15)
- DB 구조·데이터를 변경하지 않고, 전환 PR의 코드·빌드 설정을 되돌려 Java 버전으로 복구할 수 있게 유지한다. 실제 운영 중 새로 생성된 데이터를 과거로 되돌린다는 의미는 아니다. 복구 절차와 검증 결과는 구현 시 기록한다. (Q16)

## 협의 당시 기준

전환 전 2026-10-22 코드 확인 기준으로 백엔드 운영 Java 232개, 테스트 Java 72개이며 Kotlin 소스는 없다. 프론트엔드는 TypeScript/TSX이다. `build.gradle.kts`는 이미 Kotlin DSL이지만 Kotlin 소스 컴파일 플러그인은 아직 없고, 현재 Java toolchain은 25이다.

| 항목 | 제안 | 상태 |
|---|---|---|
| 전환 범위 | 운영 Java 코드 전체 전환, 테스트는 Java 유지. 필요한 빌드 설정 수정 | 확정 |
| 동작 보존 | API 경로·인증·응답·오류·추천 정책과 DB 테이블·컬럼·저장 데이터 유지 | 확정 |
| 변경 범위 | 비즈니스 로직 유지, 마이그레이션만 진행. 관리자 신규 기능 제외 | 확정 |
