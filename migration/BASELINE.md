- 기록일: 2026-10-22 (Asia/Seoul)
- 브랜치: `feature/back/kotlin-migration`
- 운영 코드 기준 커밋: `47997bf99150482084e6849635065cb2d3692718`
- 로컬 Java: GraalVM CE OpenJDK 25.0.2

- 운영 Java 코드만 Kotlin으로 전환하며 테스트는 Java로 유지한다.

## 빌드와 테스트

`back`에서 `./gradlew clean build --no-daemon` 실행: **성공**, Gradle 표시 소요 시간 1분 21초. 테스트 클래스 69개, 테스트 **515개 통과**, 실패·오류·건너뜀 0개. H2 및 격리된 Testcontainers MySQL을 사용했다. 집계는 [build-tests.json](baseline/build-tests.json)에 기록했다.

`./gradlew recommendationPrecompute --args='--help'` 실행도 성공했다. 도움말은 DB에 연결하지 않는다. 실제 지정 ID 갱신은 이번 기준 확보에서 실행하지 않았다.

## API·CLI 기준

현재 서버의 공개 API 관찰 결과는 [api-observations.json](baseline/api-observations.json)에 상태·필드·게임 ID·응답 해시로 기록했다. 토큰·비밀번호는 포함하지 않았다.

- health, 목록, Elden 검색·검색 제안, 게임 47808 상세·연관 추천: HTTP 200
- 존재하지 않는 게임 상세: HTTP 404
- 인증·기록 변경의 독립 API 시나리오와 실제 지정 ID 갱신은 별도 검증 예정

실행 중인 서버가 최신 Java 코드이며 추천 설정 3개가 모두 true임을 사용자가 확인했다. 실제 재실행 시 같은 조건을 확인한다.

전체 검증 대상:

- 서버 기동·health
- 게임 목록·검색·검색 제안·상세
- 인증·로그인·요청 검증 오류
- 기록·온보딩 맞춤 추천·상세 연관 추천
- 추천 사전 계산 도움말·지정 ID 계산

지정 ID 계산은 실제 DB를 갱신하므로 기능 기준 검증에는 격리 DB 사용을 우선한다. 응답 기록에 비밀번호·토큰은 포함하지 않는다.

## 성능 비교 조건과 결과

현재 Java 기준 맞춤·상세 추천을 순차 측정 완료했다. 각 API는 기존 SMOKE 실행으로 동작 확인 후 기본 105초·최대 VU 10명·요청 간격 1초 조건을 사용했다. 사용자 확인 기준 추천 설정 3개는 모두 true이다.

| 시나리오 | P95 (ms) | P99 (ms) | HTTP 실패율 |
|---|---:|---:|---:|
| 온보딩 맞춤 추천 | 37.4268 | 38.9330 | 0% |
| 기록 기반 맞춤 추천 | 36.1125 | 38.98523 | 0% |
| 상세 연관 추천 (게임 47808) | 30.2811 | 33.56641 | 0% |

세 시나리오 모두 응답 검사 통과율 100%이다. 맞춤 추천은 측정 반복 616회, 상세 추천은 620회를 완료했고 중단된 반복은 없었다. setup 요청은 시나리오별 응답 시간 통계에서 제외했다.

측정 지표는 [맞춤 추천](baseline/k6-personalized-java.json)·[상세 추천](baseline/k6-related-java.json)에 저장했다. k6 내보내기의 로그인 토큰이 포함되는 `setup_data`는 공유하지 않고 지표를 보존했다. 정식 측정은 API별 각 1회이므로 반복 실행 변동 범위와 성능 회귀 허용 기준은 아직 확정하지 않았다.

측정 직전 로컬 MySQL은 8.4.11, `innodb_flush_log_at_trx_commit=1`, `sync_binlog=1`, `innodb_buffer_pool_size=134217728`(128MiB), 바이너리 로그 ON이다. gamelog의 게임 287,478개, 준비 완료 게임 287,478개, 공통 후보 5,238,800행을 읽기 확인했다. DB 설정이나 추천 데이터를 변경하지 않았다.

아직 DB 스냅샷을 별도 보관하지 않았으므로 향후 데이터 변경이 있으면 동일 데이터 비교를 위한 추가 준비가 필요하다. 기존 스크린샷 기반 Java 추천 개선 수치는 Kotlin 전환의 기준 실측 결과로 대체하지 않는다.

전후 비교 시 다음을 동일하게 유지한다.

- DB 데이터·게임 ID·테스트 계정·플레이 기록
- 추천 조회·공개 제한 설정 3개
- JVM·SQL 로깅·커넥션 풀 설정
- MySQL 버전·버퍼 풀·로그 동기화 설정 및 Docker 자원
- k6 스크립트·VU·측정 시간·요청 간격·워밍업 조건
- 동기화·번역·추천 갱신 등 동시 작업의 유무

현재 실행 중인 서버의 빌드와 설정이 위 기준 커밋에 일치하는지 확인한 뒤 측정한다. P95·P99·실패율·요청 수와 측정 구간을 함께 기록하고 결과 원본을 보관한다. 환경이 확인되지 않은 측정을 확정 기준으로 사용하지 않는다.
