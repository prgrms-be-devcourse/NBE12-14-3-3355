# 게임 검색 부하 테스트 계획

상태: 2026-10-27 사용자 요청으로 시험 종료. 15개 조건 중 9개 완료, 제목순은 1 RPS만 측정. 사용자 평점순·서재 등록 수순·플레이 시간순 및 자동완성 a/al은 미측정. 추가 시험은 진행하지 않는다. JVM 재시작 전후의 실행은 원본 manifest의 재개 시각으로 구분한다.

## 합의한 목적과 범위

- 현재 게임 검색 성능의 기준선을 측정하고 부하 증가에 따른 병목 후보를 찾는다.
- 로컬 개발 환경에서 실제 테스트를 실행하고 결과와 관측 근거를 남긴다.
- 목록 검색과 자동완성은 별도로 측정한다.
- 목록 검색은 검색어, 필터, 정렬, 페이지 깊이에 따른 차이를 확인한다.
- p95 응답 시간 500ms 미만, HTTP 실패율 1% 미만을 임시 판단 기준으로 사용한다. 확정된 서비스 SLO는 아니다.
- 같은 PC에서 서버와 부하 발생기를 실행한 결과를 운영 서버의 처리 용량으로 해석하지 않는다.
- 초당 요청 수를 단계적으로 높이고 목표 요청량, 실제 처리량, 보내지 못한 요청을 구분해 기록한다.
- p95 500ms 초과는 기록하면서 계속 측정한다. HTTP 실패율 10% 이상 또는 p95 3초 이상이 30초간 지속되면 해당 시험을 중단한다.
- 서버가 응답하지 않거나 부하 발생기가 목표 요청량을 만들지 못하면 다음 단계로 올리지 않고 원인을 확인한다.
- 테스트 및 모니터링 구성 보완은 포함하지만 검색 코드와 인덱스 개선은 결과를 보고 별도로 결정한다.

## 확인한 기존 구성

- `k6/search.js`: 목록 검색, 기본 30 VU 및 1분, 반복마다 1초 대기.
- `k6/run-search.sh`: Prometheus remote write 전송 및 실행별 요약 JSON 저장.
- `compose.monitoring.yml`: Prometheus 및 Grafana 구성.
- `monitoring/prometheus.yml`: 백엔드 Actuator 지표를 5초 간격으로 수집하도록 설정.
- 기존 실행 구성과 실제 서비스 실행 상태는 구분해서 확인한다.
- 2026-10-26 읽기 전용 확인 시 MySQL, Prometheus, Grafana는 실행 중이었으나 백엔드 8080은 실행되지 않았고 Prometheus 앱 수집 대상도 down이었다.
- MySQL exporter는 현재 구성에 없다. JVM 및 커넥션 풀 지표만으로 DB 내부 병목을 확정하지 않는다.

## 확정한 실행 조건

- 백엔드는 사용자가 직접 실행한다. 실제 프로세스 인자에서 show-sql=false, ddl-auto=none, sql.init.mode=never를 확인했다.
- GraalVM JDK 25, DB 풀 최대 10개. IDE 설정에서 데이터 수집과 번역 비활성화를 확인했다.
- 게임 284,294건, 사용자 게임 기록 2건, 리뷰 2건. 집계 정렬은 대규모 사용자 기록을 대표하지 않는다.
- 검색용 기존 인덱스 idx_games_release_title, idx_games_release_title_rating, idx_games_catalog_lookup가 존재한다.
- IDE의 RECOMMENDATION_READY_ONLY_ENABLED=true 설정을 확인했다. 추천 계산 완료 여부를 확인하는 EXISTS 조건을 포함한 실행 계획은 원본 결과의 explain-ready-only.txt에 저장한다.
- 목록 조건 13개와 자동완성 조건 2개를 서로 독립적으로 측정한다. 필터 ID는 실제 filters API에서 선택한다.
- 각 조건: 단일 요청 검증 → 1 RPS 30초 예열 → 1/5/10/20 RPS 각각 120초. 실행 사이 30초 회복. 최대 100 VU.
- 처음 임시 기준을 넘긴 단계와 직전 단계는 한 번씩 재측정한다. 첫 단계부터 초과하면 첫 단계만 재측정한다.
- 최근 30초 창의 p95/HTTP 실패율을 5초 간격으로 확인한다. 완전한 창을 확보한 뒤 중단 기준 초과가 30초 지속되면 중단한다. 따라서 가장 빠른 지속 초과 중단은 약 60초 시점이다.
- 미전송 요청, 앱 지표 수집 실패, 30초간 완료 요청 없음은 조기 중단 조건이다. 중단 시험은 완료 시험과 구분한다.
- 임시 성능 기준 초과만으로 다음 단계 진행을 막지 않지만, 안전 중단이나 미전송 발생 시 해당 조건의 부하를 더 높이지 않는다.
- k6 원본 JSONL, 요약 JSON, 최근 30초 판정 이력, JVM/CPU/GC/DB 풀 관측은 k6/results/arrival-*/에 보관한다.
- Grafana 대시보드: http://localhost:3001/d/gamelog-search-arrival . 누적 p95와 최근 20초 처리량을 표시하며, 안전 중단에 사용한 최근 30초 p95와 혼동하지 않는다.
